4// Prompt Object Model (POM) — C++ port of signalwire/pom/pom.py.
5//
6// A structured data format for composing, organizing, and rendering prompt
7// instructions for large language models. The POM provides a tree-based
8// representation of a prompt document composed of nested sections, each of
9// which can include a title, body text, bullet points, and arbitrarily nested
10// subsections.
11//
12// Two classes:
13// * ``signalwire::pom::Section`` — one section in the tree.
14// * ``signalwire::pom::PromptObjectModel`` — the top-level container.
15//
16// Output formats supported:
17// * JSON via ``to_json`` / ``from_json`` (delegates to ``nlohmann::json``).
18// * YAML via ``to_yaml`` / ``from_yaml`` (minimal in-tree YAML I/O — POM
19// content is always a list of dicts whose values are strings, bools, or
20// lists; no anchors, tags, or free-form scalars to handle).
21// * Markdown via ``render_markdown`` — exact byte-parity with Python's
22// ``Section.render_markdown`` / ``PromptObjectModel.render_markdown``.
23// * XML via ``render_xml`` — exact byte-parity with Python's renderers.
24//
25// Parity contract: rendered output strings match Python verbatim (including
26// trailing newlines, joiners, and section/bullet numbering rules). The C++
27// tests in ``tests/test_pom.cpp`` are written from those Python outputs.
