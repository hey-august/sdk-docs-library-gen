◆ FormParams

using signalwire::security::FormParams = std::vector<std::pair<std::string, std::vector<std::string>>>

Pre-parsed form parameters for ValidateRequest: ordered list of (key, list-of-values) tuples.

Repeated keys are represented as one entry whose values vector holds each occurrence in submission order.

Used as one alternative in ParamsOrBody; the other alternative is the raw body string.

Legacy @signalwire/compatibility-api drop-in entry point.

If params_or_raw_body holds a std::string, delegates to ValidateWebhookSignature (Scheme A then Scheme B with parsed form).

If it holds a FormParams, treats it as pre-parsed form params and runs Scheme B directly (with URL port normalization).

Exceptions
std::invalid_argumentwhen signing_key is empty.

◆ ValidateWebhookSignature()

bool signalwire::security::ValidateWebhookSignature ( std::string_view signing_key,
std::string_view signature,
std::string_view url,
std::string_view raw_body )

Validate a SignalWire webhook signature against both schemes.

Tries Scheme A (hex JSON) first; on miss falls back to Scheme B (base64 form) with URL port normalization, repeated-key handling, and optional ?bodySHA256= body-hash check for JSON bodies on the compat surface.

Parameters
signing_keyThe customer's Signing Key. UTF-8 string. MUST NOT be empty — empty throws std::invalid_argument, that's a programming error not a validation failure.
signatureThe X-SignalWire-Signature header value (or the legacy X-Twilio-Signature alias). Empty returns false without throwing.
urlFull URL SignalWire POSTed to (scheme, host, optional port, path, query) — must match what the platform saw, see the URL-reconstruction section of porting-sdk/webhooks.md.
raw_bodyRaw request body bytes as a UTF-8 string, BEFORE any JSON / form parsing. Re-serialized JSON breaks Scheme A.
Returns
true if either scheme matches; false otherwise.
Exceptions
std::invalid_argumentwhen signing_key is empty.

◆ WrapWithSignatureValidation()

HttpHandler signalwire::security::WrapWithSignatureValidation ( std::string_view signing_key,
HttpHandler downstream,
WebhookValidatorOptions opts = {} )

Wrap a downstream cpp-httplib POST handler with SignalWire webhook signature validation.

Behavior:

  1. Read req.body (cpp-httplib has already buffered it).
  2. Pull X-SignalWire-Signature (or the X-Twilio-Signature legacy alias) from headers.
  3. Reconstruct the public URL the platform POSTed to (proxy-aware).
  4. Call ValidateWebhookSignature.
  5. On invalid / missing signature: respond 403 Forbidden with no body detail. The downstream handler is NOT called. Per the porting-sdk spec, the validator MUST NOT log which branch failed or the expected signature.
  6. On valid: call downstream(req, res). The handler can read req.body directly — cpp-httplib buffers it for repeat reads.
Parameters
signing_keyCustomer's Signing Key (SignalWire Dashboard → API Credentials). MUST NOT be empty — empty throws std::invalid_argument at wrap time, that's a programming error not a runtime failure.
downstreamHandler to invoke on a valid signature.
optsOptional URL reconstruction knobs.
Returns
A handler suitable for server.Post(path, handler).
Exceptions
std::invalid_argumentif signing_key is empty.
