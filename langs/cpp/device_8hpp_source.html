13// ===========================================================================
14// Device — the {type, params} object passed as a raw json map across the RELAY
15// calling methods that target an endpoint: connect / refer / dial / tap.
16//
17// Grounded in `porting-sdk/relay-protocol/calling.{dial,connect,refer}.params.json`
18// (extracted from switchblade `PublicCall*Params.cs`): each device is an object
19// with a REQUIRED string `type` discriminant (e.g. "phone", "sip", "webrtc")
20// and an open `params` object whose keys depend on `type`. The schema is
21// `additionalProperties:true` and does NOT enumerate the `type` values, so we
22// type the SHAPE only: `type` stays a `std::string` (open discriminant), and
23// `params` stays a free `json` map. `to_json()` yields the IDENTICAL wire shape
24// the hand-written `{{"type",...},{"params",...}}` map produces.
25//
26// Additive idiom (PORT_ADDITIONS.md): the raw-`json` connect/dial/refer/tap
27// overloads stay canonical (parity with Python's nested dict/list). `Device`
28// is a typed convenience for assembling that map with a named field instead of
29// stringly keys — `Device{"phone", {{"to_number", to}}}` reads better than the
30// brace-soup and can't typo the two top-level keys.
31// ===========================================================================
32struct Device {
35 std::string type;
38 json params = json::object();
39
40 Device() = default;
41 Device(std::string type_, json params_ = json::object())
42 : type(std::move(type_)), params(std::move(params_)) {}
43
46 [[nodiscard]] json to_json() const {
47 json j;
48 j["type"] = type;
49 j["params"] = params;
50 return j;
51 }
52};
