Class WebhookValidator

Namespace
SignalWire.Security

SignalWire.dll

Validates SignalWire webhook signatures for both Scheme A (RELAY/JSON, hex HMAC-SHA1 over url + rawBody) and Scheme B (Compat/cXML form, base64 HMAC-SHA1 over url + sortedFormParams) per porting-sdk/webhooks.md. The contract is byte-identical across all SignalWire SDK ports — see the cross-port test vectors in the spec.

ValidateRequest(string, string?, string, object?)

Legacy @signalwire/compatibility-api drop-in entry point.

If paramsOrRawBody is a string, delegates to ValidateWebhookSignature(string, string?, string, string?) (Scheme A then Scheme B with parsed form).

If it's an IDictionary or list of key/value pairs, treats it as pre-parsed form params and runs Scheme B directly (with URL port normalization).

ValidateWebhookSignature(string, string?, string, string?)

Validate a SignalWire webhook signature against both schemes.

public static bool ValidateWebhookSignature(string signingKey, string? signature, string url, string? rawBody)

Parameters

signingKey string

Customer's Signing Key from the Dashboard. UTF-8 string, secret. Empty or null raises ArgumentException — that's a programming error, not a validation failure.

signature string

The X-SignalWire-Signature header value (or X-Twilio-Signature for cXML compat). Missing / empty returns false without throwing.

url string

The full URL SignalWire POSTed to (scheme, host, optional port, path, query). Must match what the platform saw — see the URL reconstruction section of porting-sdk/webhooks.md.

rawBody string

The raw request body bytes as a UTF-8 string, BEFORE any JSON / form parsing. Re-serialization breaks the Scheme A digest.

Returns

bool

true if the signature matches either Scheme A (hex JSON) or Scheme B (base64 form, with port-normalization variants and optional bodySHA256 fallback). false otherwise.

Exceptions

ArgumentException

Thrown when signingKey is null or empty.
