Remarks

Defining a SWAIG tool's parameters in the Python reference (and, until now, in this port) means hand-writing an untyped Dictionary<string, object> of nested dictionaries — a raw JSON-Schema blob: 

new Dictionary<string, object>
{
    ["service"] = new Dictionary<string, object>
    {
        ["type"] = "string",
        ["description"] = "The service",
        ["required"] = true,
    },
};

ParameterSchema produces the byte-identical properties map type-safely: 

ParameterSchema.Create()
    .String("service", "The service")
    .String("date", "YYYY-MM-DD")
    .Enum("fmt", typeof(RecordFormat), "format")  // → enum: ["wav","mp3","mp4"]
    .Required("service", "date")
    .Build();

This is a typed convenience over the same wire output, not a new format. Build() returns exactly the dictionary you would have hand-written, so it drops straight into the existing untyped DefineTool path — which keeps working unchanged. There is no Python reference counterpart (Python builds the dict by hand); this is a .NET-only additive ergonomics layer.

Required. Required(params string[]) marks properties with the inline ["required"] = true flag this port's hand-written tool params already use (e.g. MathSkill, SpiderSkill, InfoGathererSkill). For callers that prefer the top-level JSON-Schema required: [...] array instead (the shape DataMap and the Python SWAIGFunction emit), RequiredNames exposes the same names as an ordered List<string>.

Closed sets. Enum(string, Type, string?) integrates the Tier-1 typed enums (RecordFormat, RecordDirection, TapDirection, Codec, …) by reflecting over the enum's members and emitting each member's canonical wire string (its ToWireName) into the schema enum: [...] list — so the closed set is defined once, in the enum, rather than re-typed as a string list at every call site. An explicit Enum(string, IEnumerable<string>, string?) overload remains for genuinely-open or ad-hoc value sets.
